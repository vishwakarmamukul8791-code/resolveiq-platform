Incident ID: INC-1009
Category: Database
Priority: Critical
Status: Resolved

Issue:
Application server logs showed repeated ORA-12154: TNS could not resolve the connect identifier specified when attempting to connect to the Oracle database.

Root Cause:
The tnsnames.ora file on the application server was missing the entry for the newly migrated database instance after a server migration.

Resolution:
1. Located the correct connect descriptor from the DBA team.
2. Added the missing entry to tnsnames.ora.
3. Restarted the application connection pool.
4. Verified successful connection using tnsping.

Keywords:
ORA-12154, TNS, Oracle, Database Connection, tnsnames.ora

Incident ID: INC-1010
Category: Database
Priority: High
Status: Resolved

Issue:
Application threw SQLSTATE[08001] [2002] Connection refused when attempting to reach the PostgreSQL database from the application tier.

Root Cause:
The PostgreSQL service was bound to localhost only after a configuration change, blocking connections from the application server's IP.

Resolution:
1. Updated postgresql.conf to listen on the correct network interface.
2. Updated pg_hba.conf to allow the application server's subnet.
3. Restarted the PostgreSQL service.
4. Confirmed connectivity using psql from the application server.

Keywords:
SQLSTATE 08001, PostgreSQL, Connection Refused, pg_hba.conf

Incident ID: INC-1016
Category: Application
Priority: Critical
Status: Resolved

Issue:
The batch reporting service crashed with java.lang.OutOfMemoryError: Java heap space during nightly processing.

Root Cause:
A recent change caused the batch job to load an entire month of transaction records into memory at once instead of processing in paged batches.

Resolution:
1. Analyzed the heap dump to confirm the cause.
2. Refactored the job to process records in batches of 5,000.
3. Increased the JVM heap size as a short-term mitigation.
4. Verified the job completed successfully for three consecutive nights.

Keywords:
OutOfMemoryError, Java Heap Space, JVM, Batch Processing

Incident ID: INC-1019
Category: Authentication
Priority: Critical
Status: Resolved

Issue:
Users across the organization were unable to log in, with the identity provider returning invalid_grant errors during the OAuth token exchange.

Root Cause:
The system clock on the authentication server had drifted by over five minutes due to a failed NTP sync, invalidating token timestamps.

Resolution:
1. Confirmed clock drift using ntpdate against a reliable time source.
2. Restarted the NTP daemon and forced an immediate sync.
3. Verified system time was within tolerance.
4. Confirmed successful login for affected users.

Keywords:
OAuth, invalid_grant, NTP, Clock Drift, Authentication

Incident ID: INC-1020
Category: Load Balancer
Priority: High
Status: Resolved

Issue:
Users intermittently received HTTP 502 Bad Gateway errors when accessing the customer portal during peak hours.

Root Cause:
Backend application servers were timing out under peak load because the connection pool size was set too low for the increased traffic.

Resolution:
1. Reviewed load balancer and application server logs to correlate timeout timing.
2. Increased the application connection pool size.
3. Added horizontal auto-scaling based on CPU utilization.
4. Confirmed no further 502 errors during the next peak traffic window.

Keywords:
HTTP 502, Bad Gateway, Load Balancer, Connection Pool, Auto-Scaling
